POST-AUDIT FIXES APPLIED
  1. Hardcoded admin credentials removed from backend/internal/api/auth.go.
     Login now validates local users against the database using bcrypt.
  2. JWT_SECRET fallback constant removed (backend/internal/config/config.go);
     the server now fails fast at startup unless JWT_SECRET is set (a random
     secret is generated only when ENVIRONMENT=development).
  3. Admin account bootstrapped from ADMIN_EMAIL / ADMIN_PASSWORD at startup
     (backend/cmd/server/main.go) with a bcrypt-hashed password; a warning is
     logged if they are not set.
  4. CORS wildcard removed; Access-Control-Allow-Origin is now restricted to
     the configured ALLOWED_ORIGINS / ALLOWED_WEBSOCKET_ORIGINS allowlist.
  5. Added backend/.env.example and frontend/.env.example.
  6. .gitignore updated to ignore backend/static/artifacts/*.zip,
     backend/static/artifacts/manifest.json, agent/build/, tools/agent/build/.
  7. Dead code deleted (legacy DLPService.cpp, grpc_client.*, orphaned frontend
     components/pages).
  8. Mock IPs removed from EnhancedSettingsPage.tsx audit logs.
  9. Added LICENSE (MIT) and SECURITY.md.

REMAINING (non-blocking) ITEMS
  - go vet warnings pre-existing and unrelated: classification_test.go
    TestPhase4DecisionMapping redeclared; ad_sync.go IPv6 dial formatting.
  - Open-core tier enforcement remains client-side only (see Section 3 note).

Top 3 Blockers (as originally found):
  1. HARDCODED ADMIN CREDENTIALS in the login handler.
     File: backend/internal/api/auth.go:125
     `if req.Email == "admin@pritrak.local" && req.Password == "admin123" {`
     This is the ONLY login path. Anyone who deploys the defaults can be logged
     into by anyone who reads the source. Docs even advertise these creds
     (docs/QUICK_START_GUIDE.md:94-95, 154-155).

  2. PREDICTABLE JWT SIGNING SECRET when JWT_SECRET is not set.
     File: backend/internal/config/config.go:27, 48-52
     When JWT_SECRET is unset, the server signs tokens with the constant
     "change-me-to-secure-random-secret-in-production". This public value allows
     anyone to forge valid admin JWTs.

  3. NO .env.example FILE for backend or frontend.
     Operators are not told which secrets to set (JWT_SECRET, AES_ENCRYPTION_KEY,
     DATABASE_URL, VITE_API_URL), which makes it highly likely the insecure
     defaults above are used in real deployments.

CRITICAL:
  [C-1] Hardcoded admin account (username + plaintext password).
        backend/internal/api/auth.go:125
        `admin@pritrak.local` / `admin123` is the only accepted login.
  [C-2] Fallback JWT signing secret is a public constant.
        backend/internal/config/config.go:27  -> getEnv("JWT_SECRET", generateRandomSecret())
        backend/internal/config/config.go:48-52 -> returns "change-me-to-secure-random-secret-in-production"
        (auth.go fail-fasts on an EMPTY secret, but config.go guarantees the
        secret is never empty, so the insecure constant is always used unless
        the operator explicitly sets JWT_SECRET.)

MEDIUM:

        backend/internal/api/auth.go:94 (and 95-97). Combined with C-1, this

        backend/internal/config/config.go:26
          "postgres://postgres:dev@localhost:5432/dlp_events?sslmode=disable"

        infra/docker-compose.dev.yml:27 (postgres:dev)

        should be removed/neutralized for a public repo.)
  [M-3] Committed binary build artifact + manifest.
        backend/static/artifacts/PritrakDLP-Agent-1.0.0-x64.zip  (~776 KB)
        backend/static/artifacts/manifest.json
        NOT covered by .gitignore -> will be committed with the repo.
  [M-4] Agent config ships with a local/dev backend URL.
        agent/config.json:3 -> "url": "https://localhost:8443"

3. OPEN-CORE TIER ENFORCEMENT STATUS
--------------------------------------------------------------------------------
Route Protection Status: PASS
  - frontend/src/config/tiers.ts defines routeTiers (community/starter/enterprise)
    and isRouteLocked(); useTier() currently returns 'community'.
  - frontend/src/App.tsx wraps ALL 35 routes in <ProtectedRoute> +
    <TierProtectedRoute> (verified - every route element includes both guards;
    coming-soon routes are generated through the same wrapper).
  - frontend/src/components/TierProtectedRoute.tsx:29-45 returns
    <UpgradeGateModal /> instead of rendering children when the route's required
    tier exceeds the current tier, so enterprise routes cannot be reached by
    typing the URL directly.
  - UpgradeGateModal wiring: PASS. It is driven by the uiStore
    (frontend/src/stores/uiStore.ts) and rendered both by TierProtectedRoute and
    by MainLayout (frontend/src/components/MainLayout.tsx:18).

Note / Observation:
  Tier enforcement is CLIENT-SIDE ONLY. The Go backend has no per-route
  entitlement/license checks, so a determined user can call enterprise APIs
  directly. For an open-core community edition this is acceptable if enterprise
  APIs are not exposed or are harmless, but it is worth a documented decision
  (or a reverse-proxy/license layer) before claiming hard enforcement.
